# Безопасность Tempo

Обновлено: 15 ноября 2026 (после hardening-проходки: ключи, платежи, аккаунты, напоминания).

## Ключи и секреты

- **Встроенный Gemini-ключ удалён из кода.** Ранее в клиенте был зашит пилотный ключ Google AI Studio (по явному решению владельца). Ключ проверен 15.11.2026 — недействителен (401), т.е. его раскрытие в истории git больше не даёт доступа. AI-вызовы идут только через сервер с переменной окружения `GEMINI_API_KEY`; без ключа AI-эндпоинты возвращают честную ошибку конфигурации (503 `config`), и квота пользователя при этом не расходуется.
- **Никаких секретов в localStorage** — пароли, токены сессий и ключи сервисов в браузере не хранятся. Пользовательский Gemini-ключ (необязательный) живёт только на устройстве пользователя и используется только для его собственных запросов.
- **Экспорт/бэкап не содержит личных ключей** — `apiKey` вырезается из JSON-экспорта и облачной синхронизации (`store.ts`).
- **Токен Telegram-бота засекречен на сервере** (`BOT_TOKEN`). Токен, ранее фигурировавший в переписке, считается скомпрометированным: владелец должен перевыпустить его через @BotFather перед продакшном.

## Аутентификация и аккаунты

- **Telegram initData** проверяется на сервере timing-safe HMAC-подписью по официальной схеме (secret = HMAC_SHA256(bot_token, "WebAppData")).
- **Привязка аккаунтов — по неизменяемому Telegram user ID** (`tgUserId`), не по username (username можно сменить). Один Telegram-пользователь — один аккаунт (409 при конфликте).
- **Пароли** — PBKDF2/scrypt-подобный хеш с солью, сравнение timing-safe. Rate limit на вход/регистрацию: 5 попыток/мин/IP.
- **Сессии** — серверные токены; при GDPR-удалении аккаунта отзываются все сессии.
- **Самоудаление аккаунта (GDPR)** — `/api/account/delete` требует подтверждения паролем; удаляются креды, сессии, облачный снапшот, напоминания, тред поддержки; финансовые записи сохраняются только анонимно (юридическое удержание).
- **Админ-доступ — только на сервере**: имя/пароль из env (`ADMIN_PASS`), fail-closed (без переменной админа не существует). Проверки admin-прав в коде сервера, не в клиенте. Действия админа пишутся в аудит-лог.

## API-гигиена (server.mjs)

- **CORS — строгий allow-list**: origin приложения, тот же хост, `localhost` и платформенные `*.pplx.app` (https). Чужие origin не получают `Access-Control-Allow-Origin`; без Origin заголовок не «*», а отсутствует/`null`. Никогда не `*` для аутентифицированных API.
- **Security-заголовки на каждом ответе**: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`.
- **Лимит тела запроса 12 МБ** — при превышении соединение обрывается (защита от гигантских payload'ов).
- **Rate limits**: auth 5/мин/IP, AI 30/мин/IP (burst).
- **Graceful shutdown** — по SIGTERM сервер завершает рассылку/записи и закрывает соединения, а не рвёт их посреди операции.
- **CSP** в `index.html`: скрипты только со своего домена и telegram.org, соединения только с Google AI API и собственным API.

## Платежи

- **LiqPay callback**: подпись проверяется timing-safe; активация **только по статусу `success`**. Статус `sandbox` активирует подписку только при явном `LIQPAY_SANDBOX=1` (тестовый режим, никогда в продакшне).
- **Проверка заказа**: callback обязан ссылаться на существующий pending-заказ, созданный этим сервером, с совпадением пользователя, тарифа, периода, суммы и валюты. Неизвестный заказ → 400. Дубликаты callback идемпотентны.
- **Telegram Stars**: `pre_checkout_query` обрабатывается (валидация invoice payload, ответ в течение 10с, иначе платёж падает по таймауту Telegram).
- **autoRenew = false честно**: рекуррентного биллинга нет, поэтому промисов «автоматически продлится» в UI нет.

## Данные

- **ИИ не исполняет SQL**; AI-действия валидируются по строгой схеме до записи (суммы, даты, категории, БЖУ).
- **XSS**: React экранирует пользовательский контент; `dangerouslySetInnerHTML` не используется.
- **Чанкинг Telegram CloudStorage** — данные разбиваются на куски ≤3500 символов (до 600), чтобы не упираться в лимиты платформы.
- **Напоминания**: серверный планировщик доставляет их в Telegram по таймзоне пользователя (`tzMinutes`) с дедупликацией на день. Хранение событий само по себе не означает доставку — доставка реализована отдельным планировщиком и требует `BOT_TOKEN` на продакшне.
