# Безопасность Tempo

## Реализовано

- **CSP** — Content-Security-Policy в `index.html`: скрипты только со своего домена и telegram.org, соединения только с Google AI API, `base-uri 'none'`, `form-action 'none'`. Инлайн-стили разрешены (необходимы Tailwind/React), всё остальное заблокировано.
- **Никаких SQL-инъекций** — ИИ никогда не исполняет SQL; API бэкенда нет. AI-ответы валидируются по строгой схеме до записи.
- **Никаких секретов в localStorage** — в браузере не хранятся пароли, токены или ключи сервисов. Пользовательский Gemini-ключ (необязательный) хранится локально на устройстве пользователя и используется только для его собственных запросов.
- **Данные не покидают устройство** (кроме запросов к ИИ) — персист: localStorage + Telegram CloudStorage.
- **Дедупликация** — защита от повторной записи тех же действий (hash + окно 5 минут).
- **Валидация AI** — все действия проверяются: суммы, даты, категории, БЖУ. ИИ не может создать запись с невалидными данными.
- **Подтверждение перед записью** — высокий риск действий (финансы, события) требует явного «Записать».
- **XSS** — React экранирует весь пользовательский контент; `dangerouslySetInnerHTML` не используется.
- **Экспорт данных** — JSON-файл целиком под контролем пользователя; полное удаление одной кнопкой.

## Известные компромиссы (честно)

- **Встроенный API-ключ ИИ в клиенте** — по явному запросу владельца проекта («кинь в код»). Это бесплатный ключ Google AI Studio с лимитами. Он не даёт доступа к чьим-либо данным (данные не отправляются на наш сервер — его просто нет). Если проект станет публичным, ключ следует отозвать и перенести за прокси-сервер (см. роадмап в ARCHITECTURE.md).
- **Абуз лимитов ключа** — при исчерпании бесплатной квоты ИИ перестанет отвечать; приложение продолжает работать в ручном режиме.

## Роадмап

- Прокси-функция (Supabase Edge / Cloudflare Worker) для вызовов ИИ — ключ уходит с клиента.
- Rate limiting на уровне прокси.
- Серверная аутентификация Telegram + RLS в Supabase.
