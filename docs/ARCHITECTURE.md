# Архитектура Tempo

## Обзор

React 19 SPA (Vite) + лёгкий Node.js-бэкенд без зависимостей (`server.mjs` + `ai-router.mjs`): аккаунты, оплата, поддержка и — с ноября 2026 — весь AI-трафик через серверный роутер. Ключ Gemini больше не попадает в клиентский бандл.

```
┌─────────────────────────────┐     ┌──────────────────────────────────┐
│  React 19 SPA (Vite build)  │     │  Node.js backend (zero deps)     │
│                             │     │                                  │
│  UI: Home / Assistant /     │ ──▶ │  /api/auth/*      аккаунты       │
│  Finance / Planning /       │     │  /api/billing/*   Stars + LiqPay │
│  Nutrition / Profile /     │     │  /api/ai/chat     AI-роутер      │
│  Billing / Support          │     │  /api/support/*   чат поддержки  │
│  ├─ CaptureFlow (AI-захват) │     │  /api/admin/*     админ-панель   │
│  └─ IslandBar + TabBar      │     │                                  │
├─────────────────────────────┤     │  ai-router.mjs:                  │
│  Состояние: Zustand store   │     │  - реестр проверенных моделей    │
│  персист: safeStorage       │     │  - фолбэк 3.5-lite → 3.1-lite    │
│  (localStorage + TG Cloud)  │     │  - таймауты 25с, 429/503         │
├─────────────────────────────┤     │  - стриминг SSE                  │
│  AI: lib/ai.ts              │     │  - серверные лимиты 10/100/300   │
│  → /api/ai/chat (сервер)    │     │  - гейтинг моделей по тарифу     │
│  → свой ключ (опционально)  │     │  - ключ Gemini ТОЛЬКО на сервере │
└─────────────────────────────┘     └──────────────────────────────────┘
```

## Ключевые модули

| Файл | Роль |
|---|---|
| `src/lib/store.ts` | Zustand-стор: транзакции, задачи, события, приёмы пищи, настройки, чат, история захватов. Дедупликация записей (5 мин), миграция облачных снапшотов. |
| `ai-router.mjs` | Серверный AI-роутер: реестр моделей (проверены реальными запросами), цепочка фолбэков, таймауты, стриминг SSE, промпты всех режимов (чат/действия/инсайт/финансы), персонализация. |
| `src/lib/ai.ts` | Клиентский слой: контекст реальных данных, вызов серверного роутера (стриминг), опциональный прямой вызов Gemini со своим ключом из Профиля. |
| `src/lib/validate.ts` | Строгая валидация AI-действий: типы, суммы, даты, категории, БЖУ. Всё подозрительное отбрасывается. |
| `src/lib/telegram.ts` | Telegram WebApp SDK: тема, haptic, CloudStorage, back-button. |
| `src/lib/storage.ts` | safeStorage — обёртка с in-memory фолбэком (превью-iframe блокируют localStorage). |
| `src/components/CaptureFlow.tsx` | Конвейер: ввод → AI → валидация → лист подтверждения → запись. Ничего не пишется без подтверждения. |

## Конвейер AI-захвата

1. Пользователь пишет текст / говорит / фотографирует еду.
2. `processInput` отправляет сообщение + системный промпт с контекстом реальных данных.
3. Gemini отвечает строгим JSON: `{reply, clarify, actions[]}`.
4. `validateAiActions` проверяет каждое действие (суммы > 0, корректные даты, известные категории, консервативные БЖУ).
5. Пользователь видит редактируемые карточки и подтверждает.
6. `applyActions` пишет в стор (с дедупликацией по хешу).

## Почему нет бэкенда

- Бесплатный хостинг статики не «умирает» (нет серверных процессов).
- Данные пользователя — его данные: localStorage + Telegram CloudStorage покрывают мобильный сценарий.
- Экспорт/импорт JSON — полная портируемость.
- Supabase-схема (см. `SCHEMA.sql`) подготовлена как путь миграции на серверную синхронизацию.

## Роадмап серверной части

1. Supabase Auth (Telegram login) + таблицы из `SCHEMA.sql` + RLS.
2. Edge Function для проксирования ИИ (ключ не в клиенте).
3. Stripe/Telegram Payments для подписок.
